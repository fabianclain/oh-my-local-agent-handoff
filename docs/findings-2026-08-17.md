## 1. `handoff prepare` hangs, and the timeout it already has cannot help

**Status: diagnosed, reproduced, NOT fixed.** The fix is three lines in `bin/handoff`, which the
overnight run was executing. Apply it before the next benchmark, not during one.

A field report recorded `handoff prepare` sleeping on a pipe for ~20 minutes, twice, with no
indication which command was responsible, and read it as a missing per-command timeout. There has
been a timeout since 2026-08-12 (`bin/handoff:665`, `timeout 120`), four days before that session.
So the obvious fix was already present and had not worked, which is the interesting part.

### The mechanism

`timeout` signals the process it started. A command substitution waits for the **pipe** to close,
and any process still holding the write end keeps it open — including one the timeout never
signalled.

Reproduced directly:

```
# a child that dies with its parent: timeout protects the substitution
OUT="$(timeout 3 bash -c 'sleep 30 & echo started; wait')"
  elapsed 3s    rc 124

# a DETACHED child that inherits stdout: timeout fires, the substitution does not return
OUT="$(timeout 3 bash -c 'setsid sleep 25 & echo started; sleep 100')"
  elapsed 25s   rc 124
```

Both timed out. Only the second one blocked, and it blocked for as long as the grandchild lived.

### Why it was the Browser suite

`.husky/pre-commit` in the monolith already documents the exact process:

> pest-plugin-browser starts a `playwright run-server` child that inherits stdout, so a foreground
> `php artisan test` that includes the Browser suite never returns even after every test has
> finished

That is a detached, stdout-inheriting grandchild by description. The session's criteria omitted
`--exclude-testsuite=Browser`; with the flag the same command took 0.59 seconds.

### Why rounds never hung, only `prepare`

`tools/verify-round:286` already redirects to a file:

```bash
timeout 120 bash -o pipefail -c "$command" >"$OUT" 2>&1
```

Nothing waits on a pipe, so a surviving grandchild cannot block it. `bin/handoff:665` captures
instead:

```bash
if DRY_OUT="$(cd "$REPO_ROOT" && ... timeout 120 bash -o pipefail -c "$dry_command" 2>&1)"; then
```

The two entry points differ in exactly the way that matters, which is why the failure looked
sporadic and specific to `prepare`.

### The fix

Write to a temporary file and read it back, as `verify-round` does. Killing the process group
instead (`timeout --kill-after`, `setsid`) does not fix it: a deliberately detached server leaves
the group, and the pipe is the thing being waited on regardless.

### The second half, which is about the plan and not the harness

`handoff prepare` reads the project's `PROJECT_RULES` to the model, and that file says to exclude
the Browser suite — but nothing checks the plan's own commands against it. A plan can therefore
violate a rule the harness is simultaneously reciting. Worth a check in `check-plan`: a
verification command that runs the suite without the exclusion the project's rules require.

## 2. Blade control directives are never checked *(fixed — `tools/blade-balance`)*

A round failed on one word: `@else` where `@endif` belonged. Run against the template that round
actually produced, recovered from `.handoff/runs/crawler-graphs-5b-page/tree-after`:

| gate | verdict |
| --- | --- |
| `php -l` | No syntax errors detected |
| `handoff view-lint` | passes |
| `blade-balance` | `:120: @if is never closed (expected @endif)` |

Each existing gate is correct about its own subject. `php -l` checks PHP, and Blade directives are
not PHP. `view-lint` checks HTML tag balance, the 100vh trap and headings. The breakage exists only
in the compiled view, which nothing looked at — a check that is real, and adjacent to the thing
that broke.

Zero false positives across all 172 shipped views. Not yet wired into `view-lint`.

## 3. Characters that are not the character they look like *(fixed — `tools/invisible-characters`)*

The local model wrote `5‑minute` into a docblock, with U+2011 NON-BREAKING HYPHEN. Twice, in two
separate rounds, in the same position in the same phrase. **Both rounds were accepted** — 10 of 10
and 16 of 16 criteria — and shipped.

Recovered from the run evidence:

```
crawler-graphs-1-schema  database/migrations/.../create_crawl_metric_buckets_table.php:8
crawler-graphs-2-collect app/Domains/Crawler/Services/CrawlerMetrics.php:15
```

It is valid UTF-8, it parses, it renders identically, it reads correctly at any font size. What it
breaks is the next `grep "5-minute"`, which returns nothing and looks like an answer.

The flagged set is deliberately narrow — only characters a reader and a tool disagree about. En and
em dashes are not flagged: this codebase writes prose in its comments and uses them throughout.
Zero false positives across all 1,049 shipped PHP and Blade files.

## 4. Every criterion in the corpus is satisfiable *(verified, no action)*

Before queuing any GPU time, all eight plans were run against the finished, shipped implementation
— the known-good answer by construction, so a criterion that fails there cannot be satisfied by
any correct implementation.

**All 85 judged criteria hold.** Eight shape gates (`patch-shape`, `docblock-anchor`) were listed
and not judged: they compare against a base ref, and on a clean checkout they answer a different
question than they answer mid-round.

This check cost half an hour and no GPU. Two of the four failures in the nine-round session were
defective criteria, and both would have been caught by it. It is now `bench/audit-criteria` and
belongs in front of any sequence whose criteria have not been re-read since they were written.

## 5. "Write every plan up front" and "write every test up front" contradict each other

The skill says to do both. Measured at `4b-wiring`'s own shipped commit, with the code finished
and correct, running that plan's own criterion `php artisan test --filter=Crawler`:

| when the reviewer's tests entered the tree | result |
| --- | --- |
| staged one step ahead | **346 passed** |
| all seven seeded up front | **19 failed**, 345 passed |

Same code, same criterion. The nineteen are the tests for steps 5a and 5b — work nobody had asked
the model to do yet. Seeding them early makes an honest criterion unsatisfiable, which is the most
expensive defect in this workflow: the model does not fail cleanly against an impossible check, it
contorts the code until the check passes.

The rule that survives both constraints: **plans up front, tests staged with their step.** Plans
up front because writing step 2's plan mid-round puts a file in the tree that the scope gate
charges to step 1. Tests with their step because a criterion may only ever be about the step being
run.

The staging has to happen between the previous step's commit and this step's round — which is what
`handoff sequence --before-step` is for — and the test must be **committed**, not merely dropped in
the tree, or the sequence correctly refuses to carry an untracked file into the next step.

## 6. The orchestrator can tell a bad criterion from a bad implementation

`handoff sequence --consult <provider>` was validated against a real archived rejection with known
ground truth before being trusted with a night.

Given the plan, the gates' evidence and the diff, Claude independently rediscovered the defect the
field report had found by hand: that the plan demanded one query while its own Step 4 is headed
"Two queries, and never one per point" and closes with "two queries for sixty points". It checked
its reading against the shipped tree, where the test now asserts `toBeLessThanOrEqual(2)`, and
answered `criterion-unsatisfiable`.

It correctly did **not** retry. That is the property the whole design turns on: against an
impossible criterion a retry is worse than a stop, because the local model's response to one has
already been to write `Carbon::setTestNow()` into production code to force a flag true.

## 7. `check-plan` accepts a plan whose judge does not exist

The five `local-usage-*` plans each name a test under **Files to read, not modify** — the file
that judges the round. None of those files exist. There is no `tests/Feature/LocalModel/`
directory and no fixture, and all five plans nevertheless pass `handoff check`.

`check-plan` verifies criteria and command counts, the file table, and the shape the harness
needs. It never asks whether the plan's own judge is present. A plan in that state fails every
round it is given, for a reason that has nothing to do with the model — the same silhouette as a
defective criterion, and the same cost.

The check is one line per path in the read-only table. Not applied tonight: `check-plan` is on
the path the overnight benchmark runs.

## 8. A judge written backwards from a finished page must be mutation-tested

The local-usage plans were written from the shipped page rather than recovered from a session,
which the doc that introduced them says out loud. That inverts the usual risk: a backwards-written
test does not fail to be satisfiable, it fails to *discriminate* — it passes the implementation it
was copied from and would pass a wrong one too.

So `tests/Feature/LocalModel/UsageReportTest.php` (staged at
`.claude/plans/judges/local-usage/`) was validated in both directions before being kept. A
throwaway reference implementation was written, the test run against it, then the reference
mutated once per known defect:

| implementation | result |
| --- | --- |
| correct reference | **13 passed** |
| all tokens ÷ all seconds | 1 failed |
| `max($seconds, 1)` instead of null | 2 failed |
| the two input measures added | 1 failed |
| hour taken in storage time | 1 failed |
| unaccounted rounds counted as zero | 1 failed |

Every defect that has actually shipped on this data is caught, and the reference is caught by
nothing. The reference was then deleted — writing it is the round's job.

Writing the test also found two defects in the test itself, both of which would have failed rounds
for reasons unrelated to the model: fixtures colliding on the table's
`(project, slug, provider, started_at)` unique key, and an assertion on the source name `journal`
where `LocalModelRun::KINDS` uses `work`. Neither would have been visible without running it.

**The other four judges are not written.** `local-usage` cannot run as a sequence until they are.
